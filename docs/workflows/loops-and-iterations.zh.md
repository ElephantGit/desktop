# 循环与迭代

[English](loops-and-iterations.md) | 中文

工作流有两种容器。**Loop** 带着类型化的反馈重复执行一个循环体，直到某个条件、一次显式退出或轮数上限让它结束（生成 → 评审 → 修改 → 评审）。**Iteration** 对数组中的每个元素运行一次它的区域（foreach）。两者都让外层图和每一轮单独的图保持为 DAG；不支持嵌套容器。工作流和运行的通用行为见[工作流](workflows.zh.md)和[工作流运行](workflow-runs.zh.md)。

## Iteration

`iteration` 节点拥有一个区域：React Flow `parentId` 指向它的那些节点。它的 `data.iterationConfig` 包含：

| 字段 | 含义 |
|---|---|
| `iteratorSelector` | 要遍历的数组类型变量 |
| `collectSelector` | 区域内声明的一个根变量，每轮收集 |
| `errorStrategy` | `fail`（默认）在第一个失败的轮次停止并让运行失败；`continue` 记录失败的轮次并运行剩下的 |
| `maxIterations` | 安全上限，默认 50，至少为 1 |

区域边界在解析时校验：区域非空且由来自 iteration 节点的边进入，不含 Output 也不含嵌套容器，成员的出边留在区域内，外部节点不能指向成员。

**轮次是持久化的事实**：区域内的行在 `workflow_node_runs.iteration` 中记录自己的轮次（迁移 `0012`；iteration 节点自己的行保持 `NULL`）。一轮的 `{iter}.item` 和 `{iter}.index` 与它的第一批行在同一个事务中提交，每个已结算轮次的账本条目与它的后续（下一轮、完成或失败）一起提交。引擎在内存中不保存迭代状态：当前轮次从行中重新推导，所以恢复会重放到同一个位置。

**结果**：完成时节点暴露 `{iter}.output`（`array[T]`，`T` 是收集目标的类型）、`{iter}.entries`（`array[object]`，每轮一个 `{item, status, output, error}`，与输入对齐）和 `{iter}.failed_count`（`number`）；它们的类型从不随策略变化。源数组长于 `maxIterations` 时，节点在启动时失败并给出长度和上限，从不截断；空的源立即完成。分支绕过了收集目标的轮次以失败结算，而不是读取过期的值。节点自身的失败总是让运行失败；只有区域内的失败可以被吸收。Condition 的决定按轮次记录。

**作用域**：成员能看到 `item`、`index` 和区域内上游的产物，看不到节点自己的结果；外部使用方能看到三个结果，看不到轮次绑定。

**编辑器**：节点渲染为一个嵌入的区域，带一个紧凑的标题和一个固定的内部起点（带入口端口的小卡片），它不能移动、配置或删除；它只用于展示，冻结的图把入口记为 `iteration --iteration-entry--> member` 边。作者从起点或某个成员的输出端口添加成员，可以创建多个入口分支，也可以插入到内部边上；每次插入都是一个可撤销、自动保存的编辑。拖动从不改变 `parentId`。框架保持 560×340 的最小尺寸，持久化贴合后的 `initialWidth`/`initialHeight`，可以从右下角以 20 像素为步长调整大小而不裁掉成员，折叠不改变图，成员变化时自动扩展或收紧。删除非空的框架会确认成员数量。

**运行视图**：运行视图按 `(node_id, iteration)` 分组区域状态。Theater 在顶层路径上只保留容器，并在其下投影区域 DAG；一个轮次选择器驱动所有成员的状态、对话和详情，某一轮没有运行的成员会如实显示，而不是借用其他轮次。总览根据冻结的几何信息重建框架，支持滚轮、双指、按钮和适应画布的缩放。

## Loop

根 `loop` 节点拥有 `data.loopConfig`；每个子节点同时通过 React Flow 的 `parentId` 和 `data.containerId` 声明所属的 Loop（schema 版本 2）。每个循环体是一个单独的 DAG，恰好有一个可达的子 Start。

| 字段 | 含义 |
|---|---|
| `maxIterations` | 轮数上限，1–100 |
| `maxIterationsBehavior` | 达到上限且没有其他结束方式时：`fail`（默认）或 `succeed` |
| `variables` | 携带变量：`name`、`valueType`、`initial`（`{ "kind": "constant", "value" }` 或 `{ "kind": "variable", "selector" }`）和一个 `feedback` 选择器 |
| `until` | 结束条件，使用 Condition 的 `logic`/`conditions` 语法；可以为空 |
| `outputs` | 具名导出，`{ "name": "result", "variableSelector": ["child", "output"] }` |

初始化可以读取全局变量和上游的外部节点。反馈、条件和导出可以读取已完成的循环体、携带值、全局变量和上游的外部值。外部节点只能读取 Loop 的导出，不能读取它的子节点。嵌套 Loop、归属不匹配、跨作用域的边和选择器，以及活跃节点上的无效类型，都会在任何会话启动之前被拒绝。

**轮次**：每一轮有一个新的变量池，只导入全局变量和上游的外部值，每个节点也有新的节点运行和会话。循环体排空之后，引擎从同一个已完成的池中解析所有反馈赋值，针对这一轮评估 `until`，并在一个仓储事务里要么提交下一轮的作用域，要么带着导出完成 Loop。缺失的值显式失败；从不替换成上一轮的输出。取消和子节点失败会一起结算当前轮次和 Loop；在一轮内部，失败会取消这一轮的兄弟节点并上升到 Loop 节点。Workspace 是共享的，所以文件修改会跨轮次累积。

**结束条件**：每轮之后检查条件：命中则 Loop 成功，否则开始下一轮。面板按变量类型过滤操作符，布尔值用选择器，一元操作符不显示值，比较值可以是类型化常量或 `{{#node.variable#}}` 模板（只有一个占位符的值保留绑定的 JSON 类型），多行之间可以用 AND/OR。为空和存在性检查接受未赋值的变量；其他比较会失败，而不是复用之前某一轮的值。达到上限时的失败信息保留精确的比较，并附上对最后一轮输入的简短读数（每项最多 160 个字符）。可以完全删除条件，只保留退出节点和上限。

**轮数上限**：开启"达到最大轮数时停止工作流"（`fail`）时，用尽轮数会让 Loop 和工作流失败。关闭时（`succeed`），最后完成的一轮发布导出，Loop 以 `stop_reason: loop_max_iterations` 成功，并放行下游节点。没有这个字段的旧快照使用 `fail`；运行使用其冻结的值，重启后也一样。

### 退出节点

`loopExit`（"退出循环"）属于某一个 Loop，接受入边，没有输出端口；在它前面放一个 Condition 来决定何时退出。多个分支可以各有自己的退出节点。根工作流和 Iteration 区域不能包含它。

到达退出节点会停止所属的 Loop，而不是整个工作流。调度器在同一波次中先派发就绪的退出节点再派发兄弟节点。一个 `RequestExit` 事务记录退出、时间以及来自当前已提交轮次的冻结导出，完成退出节点，并取消活跃的兄弟节点；已完成的节点保留它们的输出和历史，未开始的分支不再派发。退出不读取下一轮的反馈，也不评估任何结束条件。图的就绪顺序中第一个可达的退出节点胜出。

会话执行器随后只停止这一轮中被取消的会话，并在运行门之外等待它们的驱动结束。一个受保护的确认发布导出，并以 `stop_reason: loop_exit` 完成 Loop，之后外层图才继续。清理失败或 30 秒超时会让运行失败，而不是报告一次成功的退出；外部副作用不会回滚。持久化的请求在启动时重放，重复或迟到的确认不能让已完成的轮次复活。

### 编辑器与历史视图

编辑器会创建一个合法的 Loop 组（一个子 Start、一个子 Agent 以及它们之间的边）。默认组把子 Agent 的输出作为下一轮的 `value`，在输出非空时停止，并把它导出为 `result`。从成员的输出端口添加的成员属于该 Loop；把节点拖进框架不会建立归属。删除 Loop 会原子地删除它的后代和边，根级自动布局保留子节点的位置。

在运行中，外层路径把每个 Loop 显示为一个容器。打开它会显示第一个持久化的轮次和一个总览；轮次按钮带有实时状态，选择某一轮会同时切换成员路径、输出、检查器和对话，不会借用其他轮次的结果。成员以按定义结构排列的换行网格显示，未执行的成员放在折叠区里。Condition 卡片显示它的 IF / ELSE IF / ELSE 规则以及该轮记录的决定。"循环结果"显示已提交的导出、错误和结束原因，区分条件满足、显式退出和轮数上限。运行中或失败的 Loop 从不把部分值当作导出显示。

## 执行作用域

迁移 `0013` 给每次执行一个身份，这样重复的定义节点 id 不会互相覆盖。

- `workflow_execution_scopes` 保存根执行和 Loop 轮次。轮次有一个父 Loop 节点运行、一个从 1 开始的序号（1–100）、生命周期状态和 JSON 状态；根执行都没有，它的状态留在运行载荷中。`workflow_run_root_scopes` 指明每个运行当前的根执行。
- `workflow_node_runs.scope_id` 把每个节点运行分配到一个作用域。没有显式作用域的插入挂到当前根执行上；显式作用域必须属于同一个运行和当前根执行，作用域从不改变。一个部分唯一索引防止同一作用域中出现重复的活跃定义节点；一个 Loop 最多有一个待处理或运行中的轮次，每个序号在同一个父节点下唯一。
- 重启在重置运行的事务中创建新的根执行，所以来自旧执行的迟到回调是无害的。旧的节点运行保留它们的作用域。
- 降级越过这个迁移时，先把完整的作用域和节点快照追加到 `workflow_scope_downgrade_archive`，把带有 Loop 的活跃运行终止，并对旧的读取方隐藏子节点运行。扁平的运行、会话、Workspace 和文件不受影响；归档在之后再次升级时保留，作为历史而不是可恢复的状态。
