# 退出循环节点

[English](workflow-loop-exit.md) | 中文

从循环内节点输出连接点的加号菜单添加 **退出循环**。它归属于当前 Loop，接受入边，没有输出连接点。通过前置条件分支决定是否退出；不同分支可以分别添加退出节点。根工作流和 Iteration 区域不能包含该节点。

执行到退出节点后，只结束所属 Loop，外部工作流继续运行。沿用 Loop 已配置的输出绑定，从本轮已提交的数据中导出结果；不读取下一轮反馈，也不检查普通结束条件。输出绑定缺值时明确失败，不会使用上一轮节点输出补齐。循环变量仍表示已提交的携带值。

可以删除全部结束条件，通过退出节点或最大轮次结束循环。既未执行退出节点、也未满足结束条件时，默认达到最大轮次会失败；关闭下述开关后可正常结束。旧工作流行为保持不变，不涉及文件系统或数据库结构迁移。

## 达到最大轮次后的行为

循环节点的“最大轮次”下方提供“达到最大轮次时中断工作流”开关，默认开启。开启时，循环节点与工作流失败；关闭时，完成最后一轮后导出已有输出绑定，将循环标记为成功，并继续后续节点，不会执行额外一轮。最后一轮满足结束条件时，仍记录为条件满足。

配置保存为 `loopConfig.maxIterationsBehavior`：开启对应 `"fail"`，关闭对应 `"succeed"`。旧快照缺少该字段时默认 `"fail"`；其他值被拒绝。运行使用冻结快照中的配置，后续编辑不会改变已开始运行的策略，重启后的恢复也使用同一配置；显式切换运行快照时遵循所选快照。

开关只改变轮次上限的处理。保留正常轮次的反馈校验、条件求值和输出校验顺序；执行错误、反馈缺失或类型不符、条件求值错误、输出缺失仍然失败。输出来自最后一轮已完成的变量池，不用上一轮节点输出补齐，也不把下一轮反馈覆盖到本轮循环变量。

正常达到上限时，父节点记录 `stop_reason: loop_max_iterations`；轮次概览和循环结果显示“达到最大轮次，继续工作流”，与满足条件或显式退出区分。

## 执行与恢复

作用域调度器优先处理同一调度批次中已就绪的退出节点，避免继续派发同批次的其他节点。原子 `RequestExit` 事务记录退出节点执行、时间和冻结的输出结果，完成退出节点，并取消当前轮次仍活动的节点。已完成节点保留输出和会话历史；尚未启动的分支不再派发。多个退出节点同时可达时，按图的确定性就绪顺序选择首个。

会话执行器仅停止该作用域内已取消节点的会话，并等待其驱动任务结束，包括请求退出时尚未绑定会话的任务。现有终态保护拒绝迟到回调和会话绑定。清理在运行锁之外进行；受保护的确认回调提交冻结输出并完成 Loop，之后才继续外部流程。清理失败或超过 30 秒会使运行失败，不会报告退出成功。已发生的外部副作用不会回滚。

持久化请求支持启动后重放。启动清理保留正在等待退出收尾的 Loop。重复确认、用户取消后的迟到确认都不能重新激活已结束的作用域。成功退出后，父节点历史记录 `stop_reason: loop_exit`；轮次内部记录触发节点执行和请求时间，供后续历史展示使用。

## 验证

真实 SQLite 测试覆盖条件分支可达性、绕过反馈导出结果、输出缺失、并行回调保护、重复确认、取消及重启。完整 Backend 重开测试验证启动恢复和生产会话清理适配器。编辑器测试覆盖菜单范围、自动归属连线、终点连接点、保存及删除最后一条结束条件；导入与连线校验拒绝非法归属和退出节点出边。
