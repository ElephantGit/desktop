# 舞台中的循环历史

[English](workflow-loop-stage.md) | 中文

Agent 右侧“成果”同时展示所选轮次已完成的文本输出、文件变更和产物。文本输出直接读取该次节点执行记录；没有文件产物不代表没有成果。运行中的流式文本不进入该区域，切换轮次后不会保留上一轮输出。

条件节点使用独立卡片内容：按 IF / ELSE IF / ELSE 展示分支条件，并显示判断状态和错误，不展示 Agent 指令、输出占位或对话提示。轮次详情按作用域公开调度器已提交的分支决策，卡片高亮命中的 IF / ELSE IF / ELSE 分支，并在判断结果中显示分支名称。缺少记录时仍明确提示不可用，不借用其他轮次或下游状态推断。

循环导航采用可换行的节点网格，不再用横向嵌套框展示条件分支。默认显示本轮有执行记录的节点，未执行节点在可展开区域中保留查看入口；网格按定义结构排序，不表示精确的执行时间顺序。轮次按钮只显示轮次和状态标记，当前轮次的详细结果单独显示，避免长文案重复挤占空间。

顶部外层执行路径把每个 Loop 合并为一个容器，与普通节点、Iteration 容器并列。点击 Loop 默认打开第一轮及本轮概览。轮次按钮实时显示状态；切换轮次时同步更新本轮节点路径、节点输出、检查面板和对话会话。跨轮切换保留所选节点；该节点在所选轮次没有执行时显示“本轮未执行”，不会借用其他轮次的 Session 或输出。

舞台只展示已完成节点的输出。流式内容仍通过 Agent 卡片的对话按钮进入现有会话面板查看。新轮次和后台执行完成只更新状态，不改变用户的历史选择。点击外层 Loop 入口重新进入时回到第一轮。Loop 持久化契约中的轮次已从 1 开始，展示时不再加 1；Iteration 保留原有编号转换。

本轮概览列出各节点状态及已提交结果。独立的“循环结果”入口展示父节点已提交的导出值、错误及已记录的结束原因。工作流结果卡片展示整个运行已提交的最终输出。运行中或失败的循环不会把中间值作为成功导出结果。在更详细的元数据公开前，缺少执行记录的节点统一显示“本轮未执行”，不猜测缺失分支的原因。未区分执行作用域的产物列表不附加到循环子节点历史；每次执行的文件变更仍可在检查面板查看。

复用现有轮次记录及运行失效通知和刷新，不改变循环调度行为或存储布局。测试覆盖容器分组、从 1 开始的轮次选择、实时刷新保留选择、重新进入第一轮、隐藏未完成输出、未执行节点隔离，以及跨轮切换真实对话 Session。
