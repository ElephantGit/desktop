# Dify Loop and Iteration run results

English | [中文](dify-loop-run-results.zh.md)

Research date: 2026-09-28 (Asia/Shanghai). Scope: official Dify frontend source at commit [`a154a4d674018fd7196f8212066a61c8b928fd5a`](https://github.com/langgenius/dify/commit/a154a4d674018fd7196f8212066a61c8b928fd5a), resolved from `main` during this investigation. These are source-verified behaviors; no live Dify instance was exercised.

## Verified behavior

- **Navigation is drill-down plus independent accordions.** Expanding a container node exposes its Loop/Iteration log trigger, including the run count and failed-round count. Opening it replaces that tracing panel with a special result panel. A Back action returns to the parent. Each round is labeled `Loop N` or `Iteration N` (display position plus one), starts collapsed, and can expand independently; this is not a single selected-round tab bar. Sources: [node trigger gating](https://github.com/langgenius/dify/blob/a154a4d674018fd7196f8212066a61c8b928fd5a/web/app/components/workflow/run/node.tsx#L247-L264), [panel replacement](https://github.com/langgenius/dify/blob/a154a4d674018fd7196f8212066a61c8b928fd5a/web/app/components/workflow/run/tracing-panel.tsx#L162-L184), [Loop panel](https://github.com/langgenius/dify/blob/a154a4d674018fd7196f8212066a61c8b928fd5a/web/app/components/workflow/run/loop-log/loop-result-panel.tsx#L40-L159), [Iteration panel](https://github.com/langgenius/dify/blob/a154a4d674018fd7196f8212066a61c8b928fd5a/web/app/components/workflow/run/iteration-log/iteration-result-panel.tsx#L25-L126), [Loop count/error summary](https://github.com/langgenius/dify/blob/a154a4d674018fd7196f8212066a61c8b928fd5a/web/app/components/workflow/run/loop-log/loop-log-trigger.tsx#L60-L94).
- **Hierarchy is container → round → ordinary node trace.** Each expanded round embeds the shared `TracingPanel`; its nodes retain ordinary expandable input/process/output detail and parallel-branch presentation. The formatter removes children from the outer list and attaches them to their container by `loop_id` or `iteration_id`. This establishes the presentation pattern, not a claim that every arbitrarily nested runtime combination is supported. Sources: [formatter](https://github.com/langgenius/dify/blob/a154a4d674018fd7196f8212066a61c8b928fd5a/web/app/components/workflow/run/utils/format-log/index.ts), [shared trace renderer](https://github.com/langgenius/dify/blob/a154a4d674018fd7196f8212066a61c8b928fd5a/web/app/components/workflow/run/tracing-panel.tsx).
- **Round identity comes from execution metadata.** Loop groups prefer `parallel_mode_run_id`, then `loop_index`, preserving first-seen group order. Iteration groups use `iteration_index`. Both have a fallback that starts another group when a node ID repeats in the current group; children without execution metadata are omitted. The originally requested `format-log/loop.ts` and `iteration.ts` paths now live in [loop/index.ts](https://github.com/langgenius/dify/blob/a154a4d674018fd7196f8212066a61c8b928fd5a/web/app/components/workflow/run/utils/format-log/loop/index.ts) and [iteration/index.ts](https://github.com/langgenius/dify/blob/a154a4d674018fd7196f8212066a61c8b928fd5a/web/app/components/workflow/run/utils/format-log/iteration/index.ts). The [Iteration trigger](https://github.com/langgenius/dify/blob/a154a4d674018fd7196f8212066a61c8b928fd5a/web/app/components/workflow/run/iteration-log/iteration-log-trigger.tsx#L89-L118) can reconstruct groups from the duration map and retain failed iterations missing from that map.
- **State and duration are shown at two levels.** A round header prioritizes any failed child, then any running child; otherwise it shows duration when a nonempty duration map exists, plus a disclosure arrow. Duration is formatted to two decimals with a `0.01s` floor, including missing entries. Individual node headers show status icons, elapsed time and optional token counts; node bodies show error text when appropriate. Sources: [Loop status/duration](https://github.com/langgenius/dify/blob/a154a4d674018fd7196f8212066a61c8b928fd5a/web/app/components/workflow/run/loop-log/loop-result-panel.tsx#L50-L87), [Iteration status/duration](https://github.com/langgenius/dify/blob/a154a4d674018fd7196f8212066a61c8b928fd5a/web/app/components/workflow/run/iteration-log/iteration-result-panel.tsx#L35-L72), [node details](https://github.com/langgenius/dify/blob/a154a4d674018fd7196f8212066a61c8b928fd5a/web/app/components/workflow/run/node.tsx#L94-L340).
- **Loop has explicit variable presentation.** The container's input/output labels become initial/final loop variables. When available, `loop_variable_map` supplies a read-only JSON variable block for each round above its node traces. Ordinary nodes use read-only JSON input, process-data and output sections. Iteration's round panel has no equivalent standalone variable block. Sources: [Loop labels](https://github.com/langgenius/dify/blob/a154a4d674018fd7196f8212066a61c8b928fd5a/web/app/components/workflow/run/node.tsx#L117-L129), [per-round variables](https://github.com/langgenius/dify/blob/a154a4d674018fd7196f8212066a61c8b928fd5a/web/app/components/workflow/run/loop-log/loop-result-panel.tsx#L140-L158), [JSON details](https://github.com/langgenius/dify/blob/a154a4d674018fd7196f8212066a61c8b928fd5a/web/app/components/workflow/run/node.tsx#L301-L350).

## Recommendations for Ora (design proposals, not Dify facts)

1. Reuse one round-aware trace presentation for Loop and Iteration while keeping their domain execution and lifecycle owners separate. A shared view adapter can normalize container identity, round identity, node attempts, status, duration and detail availability.
2. Make the existing round history actionable: round → executed node → its actual inputs, outputs, errors and session. Keep stable scope/round/attempt identifiers; do not infer boundaries from repeated node IDs or confuse display numbering with identity.
3. Preserve domain-specific summaries: Loop should expose initial state, round feedback and exit reason; Iteration should expose the item and aggregated result. Add typed result summaries at the owning contract if persisted scope state is not currently public. Do not reconstruct those facts in the UI.
4. Use explicit unknown/missing duration and incomplete-detail states instead of copying Dify's `0.01s` fallback. Verify navigation isolation across rounds, repeated nodes, failed runs and nested scopes through production interfaces.
