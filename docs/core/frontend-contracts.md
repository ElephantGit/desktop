# Frontend Contracts

English | [中文](frontend-contracts.zh.md)

`@ora/contracts` is the frontend's only view of the Desktop IPC API. Rust owns the DTO shapes, the
operation catalog and the generated client wiring; TypeScript owns the shared client execution
logic and the Tauri transport. The steps for adding or removing an operation are in
[Changing the code](../development/changing-the-code.md).

## Endpoint catalog

`xtask` declares every frontend-facing operation as a `FrontendEndpoint` in namespace-scoped
modules under `xtask/src/frontend/namespaces/`. Each entry carries:

- `operation_name`: the flat wire identifier (`createTask`)
- `namespace` and `member_name`: where the operation sits on the client (`client.task.create`)
- `request_type` and `response_type`: the TypeScript DTO names
- `response_mode`: an explicitly declared `Unary` or `Stream`, never inferred from the name

The catalog is generation-only metadata. It contains no transport route, query or serialization
detail, and frontend types never come from domain entities or adapter-local structs.

Current namespaces: `project`, `task`, `workspace`, `session`, `appEvents`, `agentRuntime`,
`agent`, `agentImport`, `skill`, `skillImport`, `fileSystem`, `gitIdentity`, `workflow`,
`workflowRun`, `scheduledTask`, `plugin`, `effect`, `developerMode`, `runtimeLogLevel` and `proxy`.

## Generation

`task export-contracts` runs `cargo xtask export-contracts` and then derives `error.schema.ts` from
`dto/error.ts` with `ts-to-zod`. It writes into `packages/contracts/src`:

| Output | Content |
|---|---|
| `dto/` | One `.ts` file per contract family, generated by `ts-rs`. Fields that embed ACP payloads reference `@agentclientprotocol/sdk` instead of generating a second ACP schema |
| `dto/error.ts` | The request id and the discriminated public-error union |
| `endpoints.ts` | The endpoint manifest |
| `dto.generated.ts` | Barrel derived from the ts-rs output; there is no second type-to-file map |
| `client.generated.ts` | The static, typed client factory derived from namespaces and response modes |

Generated files carry ownership headers. `client.ts`, `client-runtime.ts`, `transport.ts` and
`index.ts` are hand-written. Export renders into a fresh temporary directory, rejects collisions,
replaces changed owned outputs and removes retired ones; unowned files are preserved and cannot be
overwritten by a newly generated name. DTO module filenames are kebab-case (`#[ts(export_to =
"workflow-run.ts")]`).

`task check:contracts` renders both layers into temporary directories and compares content and the
generated-file inventory without consulting Git or changing the checkout. CRLF is normalized to LF;
every other difference, missing file, stale file or untracked generated file fails. `task
test:frontend` runs this check first; it never repairs output.

The same export also generates the plugin protocol bindings, see
[Plugin system](../plugins/plugin-system.md#protocol-and-sdk).

## Typed client

`createContractsClient(transport)` returns a namespaced client whose type is derived from the
manifest: `ContractsClient` maps each endpoint's `namespace`/`memberName` pair into a nested object
type, and the generated factory is checked against it. Duplicate operations or members fail
generation.

For each call the client sends the operation name and the complete request DTO to the injected
transport; it never splits, renames or re-serializes fields. The `appEvents` namespace exposes
`client.appEvents.watch({})`: the stream starts with `Ready` and then carries best-effort
invalidations: `SessionTitleUpdated`, `PluginStatusChanged`, `AgentModelsInvalidated`,
`McpHealthChanged` and `WorkflowRunInvalidated`. Each names only what changed; clients re-query the
authoritative state.

## Transports

`ContractTransport` has two methods, `send` and `stream`, both accepting an optional `AbortSignal`.
Streams are cold and single-use: iterating the same `AsyncIterable` twice throws
`stream_already_consumed`.

The Desktop transport (`createTauriTransport` in `apps/desktop/web`) maps operation names to Tauri
commands and drives streams over a Tauri Channel. The Desktop-owned `src-tauri/bindings/` catalog
supplies handler paths and explicit Webview grants; export joins it with the logical catalog and
generates `tauri-bindings.generated.ts`, Rust command registration, typed stream routes and
permission lists. None of that adapter metadata enters the public manifest. Missing, duplicate,
unknown or wrong-mode bindings fail generation.

Native events that are not SDK streams keep their own route. For example, marketplace
auto-refresh state is declared by `MarketplaceAutoSyncEvent` in the plugin contracts, routed by
`apps/desktop/src-tauri/bindings/marketplace_sync.rs`, and covered by `check:contracts` through
generated listener code and serde samples.

`watchAppEvents` is an invalidation broadcast, not a replayable log. Before the Web App Shell
mounts queries or opens that stream, its platform adapter acquires the same-origin `ora:app-window`
Web Lock, so a second browser tab waits until the first closes. The Desktop adapter grants
ownership immediately because the native host owns one main window.

## Errors and localization

`decodeRemoteError` validates the `{ code, params, requestId }` shape and the UUID before checking
the generated union:

- A known code with valid parameters becomes `RemoteContractError`.
- An unknown code with a valid request id becomes `UnknownRemoteError` and keeps the raw code.
- A missing or invalid request id, or invalid parameters for a known code, becomes
  `LocalTransportError` with kind `malformed_response`.
- Network, invocation, framing, stream consumption, unsupported-operation and cancellation failures
  use finite local kinds and never invent a request id.

The App Shell localizes every error through one `localizeContractError` path backed by
`errors.<code>`, `errors.unknown` and `errors.transport.<kind>` resources in English and Chinese.
Internal and unknown errors show the request id for support; local transport errors do not. UI
components never render a technical `Error.message`, which a lint rule enforces.

## Package tests

The contracts, chat and editor packages first run `tsc --noEmit` and then execute their tests with
`deno test --no-check` under the clean-stderr wrapper. Relative imports use explicit `.ts`
extensions and directory entry files, and generation preserves them, so tests need no sloppy import
resolution or intermediate JavaScript.
