# 设置

[English](settings.md) | 中文

Ora Desktop 通过 App Shell 和基于 Tauri 的 contracts client 呈现设置。

Backend 的 `Settings` 接口统一将开发者模式、日志级别和网络代理设置的持久化操作调度到阻塞执行器。异步调用方只需等待结果，无需管理 SQLite 调度；数据库失败保留原有错误映射。同步插件市场 Git／缓存重建在宿主阻塞执行器上使用底层同步设置服务。

## 插件市场来源

在**设置 → 插件 → 管理市场**中点击**添加来源**打开弹窗，填写仓库的 HTTPS Git URL
和分支（默认 `main`），可选开启**使用代理**以使用 Ora 中配置的代理。**插件包获取方式**
默认是 **HTTPS 直接获取**；选择 **S3 签名获取（SigV4）** 后才展开 Endpoint、Bucket、
Region 和两项凭据，并与来源一起提交。URL、分支，以及 S3 模式下的这些字段都必填。
仓库地址、分支格式、S3 字段及冲突由 Backend 校验。之后仍可在来源的**编辑**入口修改
获取方式；编辑已有 S3 来源时，两项凭据留空会保留当前凭据。

弹窗打开后自动聚焦 URL。Enter 提交；取消、Escape 或关闭按钮丢弃草稿并将焦点返回
添加入口，不关闭外层设置。提交期间禁止重复提交和关闭；失败时在弹窗中显示错误并
保留输入，便于修改或重试。S3 凭据没有写入成功时，这次新增会被撤销，不会留下只配置了
HTTPS 的来源。成功后关闭弹窗并刷新来源列表。回到插件页点击**同步插件市场**
以刷新可用插件列表。

## 开发者模式

设置始终保留开发者选项分类及开发者模式开关。权威值来自 SQLite `user_config.developer_mode`，由应用层解释，前端不保存第二份副本。初始读取失败时禁用开关、隐藏开发者控件并允许重试；更新失败保留最后一次后端响应。

开发者模式只控制界面可见性，不授予权限、不改变传输授权，也不禁用后端操作。

## 开发者选项

启用开发者模式后显示进程日志级别选择器和**下载日志**按钮；关闭后卸载这些控件，但不离开当前页面。下载按钮仅在提供诊断日志能力的 Desktop 上显示，通过原生保存对话框导出当天日志，复用错误提示中的导出和通知逻辑。

日志级别动态应用于当前 Desktop 进程，并持久化至 `user_config.log_level`。选择器显示运行时的权威生效级别。启动恢复持久化偏好，仅在未设置时采用 `info`；遗留环境变量不影响级别。Trace 和 Debug 显示日志量较大的提醒。

启动恢复及失败回滚见[运行时日志](runtime-logging.zh.md)。
